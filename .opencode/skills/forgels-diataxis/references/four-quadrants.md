# Four quadrants

Source: https://diataxis.fr/ (fetched 2026-10-18)

Diataxis is a systematic approach to technical documentation authoring. It identifies four distinct user needs and four corresponding forms of documentation, in a systematic relationship. Documentation should be organised around the structures of those needs.

Diataxis solves problems of content (what to write), style (how to write it), and architecture (how to organise it). It imposes no implementation constraints.

## The four forms

- Tutorials: learning-oriented. A lesson that takes the newcomer by the hand through a series of steps to complete a project. The user learns by doing something meaningful toward an achievable goal. Purpose is to help them LEARN, not to get something done.
- How-to guides: goal-oriented. Directions that guide the reader through a problem toward a result. Assumes basic competence. Purpose is to help them get something DONE correctly and safely.
- Reference: information-oriented. Technical descriptions of the machinery and how to operate it. Led by the product it describes, not by user needs. Purpose is truth and certainty to stand on while working.
- Explanation: understanding-oriented. Discursive treatment that deepens and broadens understanding, brings clarity, light, and context. Answers "Can you tell me about ...?".

## Orientation axes

- Tutorials: practical steps serving STUDY.
- How-to guides: practical steps serving WORK.
- Reference: theoretical knowledge serving WORK.
- Explanation: theoretical knowledge serving STUDY.

## Practical consequences

- Each page serves exactly one need. Mixed pages serve none well.
- Tutorials and how-to guides are often conflated; they serve different needs (learn vs do) and must stay separate.
- Well-written how-to guides that address the right questions are usually the most-read sections.
- Reference must be austere, neutral, and structured like the machinery it describes.
- Explanation is the only kind it can make sense to read away from the product.
